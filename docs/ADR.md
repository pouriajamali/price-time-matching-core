# Decisions and alternatives

1. **Single writer, integer domain.** Serial input order is enough for this bounded matching contract and makes FIFO reproducible. Concurrent mutation, external clocks and floating prices add ambiguity without a demonstrated workload requirement. The public library explicitly requires one caller.
2. **Simple baseline before index.** `ScanMatcher` copies a plain accepted-order ledger, finds/sorts eligible makers, then replaces its state on success. `IndexedMatcher` uses safe BCL sorted price levels, linked FIFO nodes and ID lookup. This improves the representation of cancellation and price traversal; no measured speed improvement is claimed. Allocation failures are not transactions.
3. **Plan before mutation.** The index plans every maker quantity, checked global total and prospective resting capacity before changing an order. A capacity rule based only on current occupancy would wrongly reject crossing takers. An internal test seam reaches otherwise impractical Int64 boundaries; no public counter-import path exists.
4. **Bound lifetime identity.** Remembering closed IDs prevents silent reuse, but an unbounded set would invalidate a bounded-system claim. Therefore accepted identity capacity is separate from resting capacity and exhaustion is explicit.
5. **Independent evidence.** Python chooses one best maker at a time by scanning a copied dictionary. It shares neither the .NET index nor its clone/match implementation. It compares every ordered trade and full ledger digest, final priority queues and conservation. Deliberate corruptions must be rejected. Two agreeing C# implementations alone are insufficient.
6. **Correctness adapter, no speed headline.** Full ledger hashing and snapshots deliberately add work. End-to-end run duration is a practical timeout only. Any future timing experiment needs the separate evidence bench's schedule, cutoff, rejection/censoring and raw-data discipline. Unsafe code, custom lock-free structures, Rust/C++, SIMD and AOT have no demonstrated need here.
7. **Explicit recovery boundary.** Retained ordered input can rebuild a fresh instance. WAL, checkpoints, exactly-once external delivery and live venue recovery are separate contracts, not implied by deterministic replay.
