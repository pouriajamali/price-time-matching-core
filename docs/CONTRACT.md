# Matching contract v1

Single synthetic instrument, one sequential caller, in-memory state. Positive integer price ticks and quantities 1..1,000,000. IDs match `[a-z0-9][a-z0-9-]{0,31}`. Supported commands are limit and cancel only. Every accepted command, including cancel, advances signed Int64 accepted sequence by exactly one. Rejections do not advance it. No wall-clock timestamps or thread arrival order define priority.

Buy crosses the lowest resting ask at or below its limit; sell crosses the highest resting bid at or above its limit. At one price, smaller original accepted sequence executes first. Partial fills keep the maker's original sequence. A trade uses resting maker price and has ID `acceptedCommandSequence:withinCommandOrdinal`, ordinal starting at one. Trades are returned in execution order. Unfilled taker quantity rests at its own limit. There is no replace or market-order conversion.

For every accepted order: `acceptedQty = remainingQty + executedQty + cancelledQty`. Per trade, maker and taker executed quantities increase equally. Global executed quantity counts each match once, so `globalAcceptedQty = totalRemainingQty + 2 * globalExecutedQty + globalCancelledQty`. Global executed notional is checked sum of `tradePriceTicks * tradeQty`; its unit is tick-quantity, not money.

Duplicate IDs, including already filled/cancelled IDs, are rejected for the lifetime of the instance. Unknown cancel rejects `UNKNOWN_ID`; filled/cancelled cancel rejects `NOT_RESTING`. Identity registry maximum 100,000, resting maximum 10,000. Capacity is prospective: a fully filled taker may be accepted at a full book; closing a maker can free a resting slot. Capacity rejection does not reserve ID or sequence. Explicit smaller limits are permitted by library `Limits`, within these maxima; CLI uses maxima. Recreating the instance clears its ID registry as well as the book.

All command/trade-sequence construction and cumulative accepted/executed/cancelled/notional values use signed Int64 without wrap. When accepted sequence reaches Int64.MaxValue, the instance is terminal: all further valid commands reject `SEQUENCE_EXHAUSTED`, including cancels. Match ordinal is bounded by at most 10,000 makers per command. Plan/clone checked arithmetic and capacity before committing any mutation. Rejection returns no trades and the prior state hash. OOM, process crash and external failure are outside this domain-atomicity promise. Internal friend-test counter seeds exercise overflow; they are not supported import/recovery state and cannot be supplied through CLI.

Wire v1 is case-sensitive JSONL. Required `kind`/`orderId` strings, optional nullable side/priceTicks/quantity. Cancel requires all three null/absent. Duplicate/unknown keys, null required strings, integer strings, fractional/out-of-Int64 numbers and nesting beyond eight deny the whole file before processing. UTF-8 has no BOM; LF and CRLF are accepted, bare CR/blank rows denied, final LF optional. Input max 8 MiB, frame max 4,096 UTF-8 bytes, commands max 20,000. The bounded stream read remains capped even if input changes during reading; receipt SHA identifies the bytes actually processed, not a prior file timestamp.

Output is a fresh directory. Each completed command has exactly one event with inputIndex, normalized command, result and hash. Canonical hash is ASCII: five global values (accepted sequence/quantity, executed quantity, cancelled quantity, executed notional), each decimal plus LF; then accepted orders sorted ordinal by ID, fields `id|side|price|acceptedSeq|acceptedQty|remaining|executed|cancelled` plus LF. IDs forbid delimiters. State hashes are integrity/equality evidence, not signatures. Final full ledger and sorted resting-priority ID arrays must also agree with the independent model.

Replay budget 60 seconds checked between commands, events max 32 MiB, final snapshot max 32 MiB. Processing/output failure leaves no passing receipt; `events.incomplete.jsonl` can be retained for diagnosis. A successful CLI receipt is not independent correctness proof. Replaying the same exact ordered input is deterministic in v1. Nothing persists as a recoverable live book: after process stop, start fresh and replay retained input. No exchange protocol, real trade, self-trade control, account, risk limit, strategy, fee model, OS scheduling guarantee, production capacity or latency claim.
