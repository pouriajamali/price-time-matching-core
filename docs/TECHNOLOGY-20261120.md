# Technology selection and local validation - 2026-11-20

The selected production technology remains **.NET SDK 10.0.404, runtime 10.0.15, net10.0, C# 14 and xUnit 4.0.3**. The [official .NET 10 release metadata](https://builds.dotnet.microsoft.com/dotnet/release-metadata/10.0/releases.json) identifies these SDK/runtime servicing versions as current active LTS. [Microsoft's download page](https://dotnet.microsoft.com/en-us/download/dotnet/10.0) associates SDK 10.0.404 with runtime 10.0.15 and C# 14. The existing M1 release already carries those pins.

.NET 11.0.100/runtime 11.0.0 and C# 15 are stable, but this bounded, BCL-only matching lab needs none of their new language features. A major retarget solely to increase the version would create a separate platform/SDK/package qualification obligation without a required product behavior. The SDK 11 source experiment is not the selected app upgrade: no .NET 11 runtime or compiler was executed, and no .NET 11 package is published. Existing .NET 10 runtime/application/CLI sources, package locks, matching-v1, capacity fixtures and independent oracle are preserved exactly.

The affected improvement is a local, source-bound verification route under the same resource envelope, without GitHub Actions: native Ubuntu 24.04, actual nonroot UID, canonical single heavy lane, CPU 2, memory 2 GiB, swap 0, tasks 128, stopped-child identity/cgroup checks before execution, bounded deadline, storage and logs, and exact-own terminal/release. Existing validated public inputs can be reused as data; another project's host/caps/admission cannot substitute for this consumer's checks. Private run receipts identify the actual source, inputs and measured outcomes.

The accepted Windows/Linux public distribution remains [v0.1.0-preview.2](https://github.com/pouriajamali/price-time-matching-core/releases/tag/v0.1.0-preview.2), runtime source [90ecf0d07b8486bd208ba2498ba6933d75fbcdbd](https://github.com/pouriajamali/price-time-matching-core/tree/90ecf0d07b8486bd208ba2498ba6933d75fbcdbd). Those accepted public bytes are not replaced or re-released. A locally rebuilt verification package is a separate private candidate, identified by its own source commit, and does not replace the accepted runtime distribution. Historical exact-tag CI remains historical; CI for this task is **NOT_RUN per owner instruction**. No Actions event, dispatch, rerun, new tag or release is needed.

The available Windows 26H2/build26300 host is not treated as newly vendor-supported/admitted for .NET 10 or 11. Keeping the unchanged, already accepted public Windows bytes does not certify a new Windows runtime build. Local Linux receipts likewise prove only their exact source/host/input scope, never speed, production suitability, exchange conformance or financial results.
